**## Spec for creating Recipe Box, locally run endpoints and acceptance tests**

**WHY** - Need to create a Recipe Box with 5 endpoints, running locally and using synthetic data.

**WHAT** - Implement the acceptance tests for the Recipe Box. Write the endpoints to:

* `getRecipe` - GET - Get a specific recipe
* `createRecipe` - POST - Create a new recipe
* `getAllRecipes` - GET - Get all recipes
* `updateRecipe` - PUT - Update an existing recipe
* `removeRecipe` - DELETE - Remove a recipe

---

## RULES/CONSTRAINTS:

**0.** There must be **5 recipes** in the recipe list as synthetic data. An example of a recipe item:

```python
recipes = [
    {
        "id": 1,
        "name": "Pasta",
        "ingredients": [
            "Dry pasta",
            "Tomato sauce",
            "Salt"
        ],
        "instructions": "Boil the pasta, drain it, then add tomato sauce and salt.",
        "created_by": "Tia",
        "creation_date": "2026-09-14",
        "rate": 5
    }
]
```

**1. getRecipe** - Must receive a `recipe_id` and check whether a recipe with that ID exists in the recipe list.

Possible responses:

* `200 OK` - Recipe found
* `404 Not Found` - Recipe does not exist

Example:

```text
GET /recipes/1
```

---

**2. createRecipe** - Receives a recipe item and adds it to the recipe list.

The `id` and `creation_date` should be generated by the API.

Possible responses:

* `201 Created` - Recipe successfully created
* `400 Bad Request` - Invalid recipe data

Request body:

```json
{
    "name": "Pasta",
    "ingredients": [
        "Dry pasta",
        "Tomato sauce",
        "Salt"
    ],
    "instructions": "Boil the pasta, drain it, then add tomato sauce and salt.",
    "created_by": "Tia",
    "rate": 5
}
```

Response:

```json
{
    "id": 6,
    "name": "Pasta",
    "ingredients": [
        "Dry pasta",
        "Tomato sauce",
        "Salt"
    ],
    "instructions": "Boil the pasta, drain it, then add tomato sauce and salt.",
    "created_by": "Tia",
    "creation_date": "2026-09-14",
    "rate": 5
}
```

---

**3. getAllRecipes** - Receives no parameters and returns the current recipe list.

Possible response:

* `200 OK` - Returns the list of recipes

The endpoint should return all recipes currently stored in the recipe list.

---

**4. updateRecipe** - Receives a `recipe_id` and the updated recipe item.

The endpoint should:

* Check whether the recipe exists.
* Update the existing recipe if it exists.
* Keep the existing recipe `id`.
* Return the newly updated recipe.
* Return an error if the recipe does not exist.

Possible responses:

* `200 OK` - Recipe successfully updated
* `400 Bad Request` - Invalid recipe data
* `404 Not Found` - Recipe does not exist

Example:

```text
PUT /recipes/1
```

Request body:

```json
{
    "name": "Tomato Pasta",
    "ingredients": [
        "Pasta",
        "Tomato sauce",
        "Garlic",
        "Salt"
    ],
    "instructions": "Boil the pasta, prepare the sauce, then combine them.",
    "created_by": "Tia",
    "rate": 5
}
```

---

**5. removeRecipe** - Receives a `recipe_id`, removes the recipe item from the recipe list, and returns a successful response.

Possible responses:

* `204 No Content` - Recipe successfully deleted
* `404 Not Found` - Recipe does not exist

After successful deletion, the recipe should no longer exist in the recipe list.

---

## TASKS -

**1. Write acceptance tests for 5 endpoints**

Touches: `tests/` folder

Verify:

* Acceptance tests exist for all 5 endpoints.
* Tests cover successful requests.
* Tests cover relevant failure cases.
* Tests verify the expected HTTP status codes and response data.

---

**2. Implement recipe list with synthetic data.**

Touches: `src/data.py`

Verify:

* Recipe list contains exactly 5 recipes initially.
* Each recipe contains the required fields.
* Recipe IDs are unique.
* The synthetic data meets the constraints defined above.

---

**3. Implement each of the 5 endpoints.**

Touches: `routes.py`

Verify:

* Each endpoint follows the specification.
* Each endpoint passes its acceptance tests.
* Correct HTTP status codes are returned.
* Non-existent recipes are handled correctly.
* Created, updated, and deleted recipes correctly change the recipe list.
